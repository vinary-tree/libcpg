# T4.2 exact expression-equivalence formal plan

## Purpose and trust boundary

This plan governs pgmcp task `dovetail-x-t4-2`. It fixes the logic that must be
verified before libcpg implements the Replete adapter. The adapter consumes
only complete, live, pure [`ExpressionIr`](../api/expression-ir-reference.md)
artifacts; it neither parses source text nor mutates the Code Property Graph
(CPG). Replete supplies exact congruence closure, bounded equality saturation,
and proof tapes. Libcpg retains responsibility for language semantics, scope,
stable source identities, and the interpretation of incomplete results.

An *e-class* is a set of terms currently known equal. *Equality saturation* is
the monotone process of applying sound equations until no configured equation
adds knowledge or a declared bound stops the run. This follows the rebuilding
architecture described by Willsey et al.
([DOI 10.1145/3434304](https://doi.org/10.1145/3434304)). “Exact” below means
exact membership in the configured, typed equational model—not whole-program
behavioral equivalence.

## Mathematical contract

Let `C` be the finite set of candidate expression roots. Each candidate `c`
has a stable source identifier `n(c)`, lexical scope `s(c)`, semantic profile
`p(c)`, and admission mode `m(c)`. The admission predicate is:

```math
A(c) \iff m(c)=\mathrm{PureLive}.
```

A rewrite edge may join `x` and `y` only when both endpoints are admitted and
their boundaries agree:

```math
R(x,y) \Longrightarrow
A(x)\land A(y)\land s(x)=s(y)\land p(x)=p(y).
```

The modeled equality `E` is the reflexive, symmetric, transitive, congruence-
closed relation generated by exact structural identity and named, certified
rewrite edges. A public positive result additionally requires a replayable
proof `P`:

```math
\operatorname{Positive}(x,y) \Longrightarrow
A(x)\land A(y)\land E(x,y)\land P(x,y).
```

A negative result is stronger than failure to discover a path. It requires
complete saturation, complete provenance, supported endpoints, and absence
from `E`. Every other outcome is `Inconclusive` or `Unsupported`.

## Proof-construction ledger

The failed proof strategies are recorded so later work does not repeat them:

1. The first TLA+ draft declared `blockedMode` after an operator referenced it.
   SANY rejects that ordering; all state variables now precede dependent
   operators.
2. Rocq did not infer both directions needed by `Nat.le_antisymm` from a
   one-premise tactic application. The proof now supplies both inequalities
   explicitly and uses the standard verified linear-arithmetic tactic only for
   the impossible pair of strict inequalities.
3. Ambient `Variable` declarations outside a `Section` are rejected by the
   configured Rocq warning policy. Equality and proof relations now live in an
   explicit section; the edge-set monotonicity theorem is outside it so both
   relation parameters are visible.
4. This Rocq standard-library version does not export the attempted
   `StronglySorted_app` lemma. Canonical output ordering is instead proven by
   structural induction over `StronglySorted`, with an explicit `Forall_app`
   step for the new terminal pair.

These were specification/proof-construction failures, not counterexamples to
the contract. The final run completes every model and theorem without axioms,
assumptions, or admissions.

## Model-to-code sequence

The implementation must follow this order:

1. Verify all three formal models and record their exact output.
2. Freeze the public completion and evidence types from EQ-01 through EQ-14.
3. Add the minimal pinned Replete dependency boundary; never use a semantic
   fallback or a second equality engine.
4. Implement flat, iterative IR-to-e-node lowering and deterministic grouping.
5. Compile only named rewrites authorized by the semantic profile and node
   certificate; preserve their labels in Replete provenance.
6. Convert Replete completion and explanation states without collapsing any
   limited state into absence.
7. Add semantic Type-4 evidence through a new additive clone API, leaving the
   predecessor taxonomy untouched.
8. Extract the table above into example, exhaustive, property, parser,
   differential, serialization, cap, and small-stack lifecycle tests.

## Scope exclusion

MeTTaIL is entirely read-only and outside this implementation. No MeTTaIL
worktree, manifest, source, test, documentation, generated language, or runtime
may be changed. The standalone Replete repository may be read at its committed
revision; T4.2 changes only libcpg's dedicated feature worktree and pgmcp
tracker evidence.
